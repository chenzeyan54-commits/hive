- Repair the per-hive authorization annotations on the `hive-terminal` Ingress of already-provisioned spokes. The provisioning template renders `auth-url` / `auth-signin` / `auth-response-headers` correctly and a test asserts it, but the deployed fleet had drifted and every hosted spoke checked was missing them, because nothing ever repaired annotations post-provision: the only post-provision Ingress mutation is the vanity-host attach loop, which appends `spec.rules` entries and TLS hosts and never reads or writes `metadata.annotations`. A new bounded sweep (modelled on the per-hive env reconcile: same eligibility filter, reachability breaker, kubectl timeout and per-cycle patch cap) merge-patches the missing annotations back. It compares values rather than mere presence, so an `auth-url` left pointing at a previous hub URL or a *different* hive is treated as drift instead of looking converged. This is defense in depth only — the proxy's own fail-closed `/terminal` gate is what actually contains an exposed spoke, because it ships in the image and needs no hub action.
