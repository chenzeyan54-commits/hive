- Hive refuses to file an issue that is still the template the agent was shown, instead of dutifully creating it ([#7153](https://github.com/hivecommons/hive/issues/7153), [#7141](https://github.com/hivecommons/hive/issues/7141)). The guide agent emitted its prompt skeleton verbatim and hive filed it as a real issue titled `[guide] <specific description of the documentation gap>`, whose body was `## Documentation Gap\n\n<what is missing or incorrect>` — placeholders never substituted, and those `\n` literal backslash-n rather than line breaks, so the whole report rendered as a single unbroken line describing nothing. `repo_ref_validate.go` already caught this exact copy-the-template-literally failure one field over, in `--repo "<org>/<target-repo>"`, but a repo name has a tiny legal charset to lean on and an issue title does not; worse, a placeholder title *succeeds* at the API, so nothing ever pushed back and the filing survived as work a human had to read, recognise as empty, and close by hand. `CreateIssue` now rejects an unsubstituted `<…>` span in the title or body, and a body carrying literal `\n` escapes with no real line break anywhere, before it spends a single API call — the same fail-closed posture and the same placement as the repo-ref guard, and deliberately the opposite of the dedupe and rejected-twin gates beside it, which infer something about the world from a lookup that may have failed and so file on doubt. The refusal names the offending span, because the fix belongs in an agent's output and the agent reads the error on its next kick. The match is kept narrow on purpose so a legitimate filing is never refused: markup (`<details>`, `<img src="…">`), autolinks (`<https://example.com>`), generics (`List<T>`) and ordinary arithmetic prose (`a < b and c > d`) are all left alone. The title is held to a stricter rule than the body: a GitHub title is plain text that renders no markup, carries no autolinks and holds no code, so a single-word `<analysis>` there is a placeholder in a way it simply is not in a body. That distinction is what catches [#7141](https://github.com/hivecommons/hive/issues/7141), the same skeleton filed by the *scanner* agent rather than the guide — which is how this was established as a cross-agent bug and not one agent's quirk. Its body placeholders are single words and stay deliberately unmatched by the body rule; the title rule and the literal-`\n` rule each refuse it independently, so correcting only one of the two cannot sneak an empty skeleton through.
